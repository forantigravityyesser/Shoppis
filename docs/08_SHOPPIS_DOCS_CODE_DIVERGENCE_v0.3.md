- **Док:** `03 §23`, `04 §11`; детали — `11 §S3`.
- **Сейчас:** уведомления best-effort + серверный гейт `telegram_identities.notifications_enabled`;

  ретраи независимо от транзакции заказа.

## S3 — средне

### [ ] 3.1 Серверный image pipeline
- **Док:** `04 §6`, `03 §7`; детали — `11 §S2`.
- **Сейчас:** клиентский crop/сжатие в WebP (4:5 full+thumb, категория 320, баннер 1100),
  «сироты» удаляются best-effort.
- **Задача:** серверная MIME/контент-валидация, derivatives, strip metadata, reject malformed.

### [ ] 3.2 Поиск: спека `title + description` vs код `title`
- **Док:** `02 §15`.
- **Факт:** витринный поиск (`storefront_catalog_products_read`) и seller-поиск фильтруют **только
  по `title`** (`ILIKE`, literal search). Спека MVP говорит `title + description`.
- **Решение:** либо расширить поиск на `description`, либо поправить спеку на `title`-only (плюс,
  при желании, SKU после `2.2`).

## S4 — DECIDE / косметика

### [ ] 4.1 `products.sku`
- **Док:** `06` ADR-06.4.
- **Факт:** колонка есть (миграция `0009`), но в формах/поиске не используется, unique-индекс
  `(store_id, sku)` **не создан**.
- **Решение:** довести (поле + поиск + уникальность) или удалить колонку.

### [ ] 4.2 `product_groups`
- **Док:** `03 §5`, `16 FD-5`.
- **Факт:** `product_groups` + `products.product_group_id` не используются; связь карточек —
  `product_links`.
- **Решение:** удалить при чистке схемы или задействовать под будущую группировку.

### [ ] 4.3 Legacy-колонки и dev-пути
- `stores.owner_telegram_id` (NOT NULL, legacy), `stores.seller_contact` (legacy).
- `DEV_AUTH_MODE` + `store-repository.dev.ts` (LOCAL-путь, прод безопасен по умолчанию).
- Чтение legacy-ссылок `store_<internal_id>` (интент сохранён до миграции внешних ссылок).
- **Решение:** удалить после стабилизации данных/ссылок.

### [ ] 4.4 Buyer post-delivery feedback
- **Док:** `02 §8`.
- **Факт:** спека описывает flow после `RECEIVED` (непрочитанное состояние, рейтинг/skip, причина
  отказа от покупателя) — в коде его нет. Отзывы/вопросы работают отдельно и **без** verified
  purchase (`02 §9`).
- **Решение:** реализовать flow или явно перенести в roadmap (`16`).

### [ ] 4.5 `useAppInit` напрямую читает `window.Telegram`
- **Док:** `04 §9.0`; детали — `11 §S2`.
- **Факт:** bootstrap-код presentation-уровня обращается к Telegram SDK для safe-area/fullscreen.
- **Решение:** тонкий bootstrap-слой (сознательное исключение, зафиксировано).
